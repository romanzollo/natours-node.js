# Natours

Веб-приложение для просмотра и бронирования туров: каталог, личный кабинет, отзывы и оплата онлайн.

---

## О проекте

Это учебный full-stack проект, который я развивал от базового API до полноценного приложения с серверным рендерингом и деплоем. Здесь я отрабатывал типичный продакшен-стек Node.js: REST API, аутентификацию, работу с MongoDB, загрузку и обработку изображений, интеграцию платёжного провайдера и настройку безопасности на уровне middleware.

Пользователь может зарегистрироваться, восстановить пароль по email, просматривать туры с фильтрацией и сортировкой, читать и оставлять отзывы, бронировать тур через YooKassa и видеть свои поездки в личном кабинете. На странице тура отображается маршрут на Яндекс.Картах. Для администратора доступно управление турами, пользователями и ролями.

---

## Возможности

- REST API (`/api/v1`) для туров, пользователей, отзывов и бронирований
- JWT-аутентификация с httpOnly-cookie и защищёнными маршрутами
- Серверный рендеринг страниц (Pug) и клиентский JS для интерактивных частей
- Оплата через YooKassa (создание платежа, редирект, webhook и подтверждение брони)
- Загрузка и ресайз обложек туров и аватаров (Multer + Sharp)
- Транзакционные письма (Nodemailer): приветствие, сброс пароля
- Rate limiting, Helmet (CSP), XSS-санитизация, HPP, безопасный парсинг query

## Чему посвящён проект (учебные задачи)

В рамках проекта я проходил путь от CRUD и схем Mongoose до более «взрослых» тем:

- проектирование RESTful API и фабрика контроллеров для повторяющейся логики;
- валидация данных, кастомные ошибки и централизованный error handler;
- агрегации, виртуальные поля и populate в MongoDB;
- middleware-цепочки, защита маршрутов и ролей (`user` / `admin` / `lead-guide`);
- работа с файлами и оптимизация изображений на сервере;
- интеграция внешнего API (платежи, карты) и обработка webhook;
- подготовка к production: `trust proxy`, сжатие ответов, переменные окружения, сборка фронта и CI-friendly build.

## Быстрый старт

**Требования:** Node.js 20.x, MongoDB Atlas (или локальный инстанс).

```bash
# установка зависимостей
npm install

# скопировать переменные окружения
cp .env.example .env
# заполнить DATABASE, JWT_SECRET, ключи почты, YooKassa, Yandex Maps

# разработка: API + watch для клиентского JS
npm run dev:full

# только сервер
npm run dev
```

Приложение по умолчанию: `http://localhost:8000` (порт задаётся в `.env`).

### Скрипты

| Команда | Назначение |
|---------|------------|
| `npm run dev` | сервер с nodemon |
| `npm run dev:full` | сервер + Parcel watch |
| `npm run build` | сборка JS + проверка зависимостей |
| `npm start` | запуск в production |

## Переменные окружения

Шаблон — в [.env.example](.env.example). Минимально нужны строка подключения к MongoDB, секрет JWT, настройки SMTP и ключи YooKassa / Yandex Maps для полного функционала оплаты и карт.

На Render и Fly.io те же переменные задаются в панели сервиса (файл `.env` в репозиторий не коммитится).

---

## Деплой

- **Render** — конфиг в [render.yaml](render.yaml): `npm ci`, `npm run build`, `npm start`
- **Fly.io** — [fly.toml](fly.toml) + [Dockerfile](Dockerfile)

Перед деплоем убедитесь, что в окружении production заданы все секреты из `.env.example`.
